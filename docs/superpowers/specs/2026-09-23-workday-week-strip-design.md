# 「工作日」那行的本周七格 设计

日期：2026-09-23
状态：已实施（2026-09-23，见 plans/2026-09-23-workday-week-strip.md）

> **实施后更正（2026-09-23）**：§2 的配色经用户三轮调整，最终定为
> 「**要弹 = 便签黄底（`STICKY`）/ 不弹 = 纸底 `INK_FAINT` 淡字 / 今天 = 墨框（`EDGE`）**」。
> 过程：起草时定「墨底纸字 + 黄描边」→ 用户改成「黄底 + 红框」→ 看过觉得红框怪 → 最终「黄底 + 墨框」。
> 测试断言断的是底色 `STICKY`、今天框色 `EDGE`。
> 挑「今天」标记时的推理（值得留）：**填充**维度被"要弹/不弹"占了、**颜色**维度被"黄/淡/红"占了，
> 所以今天只能靠**位置或形状**表达；试过并否掉：红框（像报错）、字加下划线（黄底上太弱）、不标（得自己数格子）。

## 1. 背景与目标

「循环」选「工作日」时，编辑框里只有一行字：

```
工作日（按国家法定节假日，数据到 2026-12-31）
```

它只说了"按什么算"，没说"算出来是什么"。用户看不到本周到底哪天要弹 —— 尤其碰上调休
或节假日（2026-09-25 中秋那周，周五就不弹），得等到那天没弹窗才发觉。

本次换成一排**本周七格**：要弹的深、不弹的淡，一眼看完这一周。

## 2. 形态（已与用户确认，预览图 `_ui_probe3/90_final.png`）

```
重复    按星期   [工作日]   按日期区间
本周    ▓ ▓ ▓ ▓  五  六  日      数据至 12-31
        └─ 要弹 ─┘ └─ 不弹（淡）─┘
```

- 前缀是 **「本周」**，不是「工作日」——「重复」那排已经亮着"工作日"，重复；而"本周"
  回答了"这是哪一周"这个必须交代的问题，否则那排格子会被读成**规则**而不是**本周实况**。
- 七格与「按星期」同形：同样的字（`WEEKDAY_LABELS`）、同样的字号（`theme.ui(10)`）、
  同样的 `padx=8 pady=3`。**但只读**，不响应点击。
- **要弹 = 墨底纸字**（`INK` 底 / `PAPER` 字，深），**不弹 = 纸底淡字**
  （`PAPER` 底 / `INK_FAINT` 字）。
  **刻意不用便签黄底** —— 黄底与「按星期」勾一~五 长得一模一样，会让人以为
  "工作日 = 按星期勾一~五"，而那正是本次功能要分开的两件事。
- **今天那格加一圈`STICKY` 黄描边**（用户要求）。选黄是因为它是唯一在**深色格子和
  淡色格子上都看得见**的颜色；不用红笔 —— 红笔在这套里专指"已错过"。
- 末尾保留数据覆盖信息，缩短成 `数据至 12-31`（原句太长，实测会把格子挤出窗口）。

## 3. 数据

新增 `holidays.week_of(day) -> list[date]`：`day` 所在那周的周一到周日（纯日期计算）。

判定一律走现有的 `holidays.is_workday(day)`，**不新增任何节假日逻辑**。

数据没覆盖到的年份本来就是"回退周一至周五"，格子会如实显示成一二三四五深、六日淡 ——
不需要特殊处理，也不额外提示。

## 4. 实现

| 文件 | 改动 |
| --- | --- |
| `reminders/holidays.py` | 新增 `week_of()`（4 行，纯日期计算） |
| `reminders/theme.py` | 新增颜色 token `INK_FAINT`（"不弹"那格的淡字色） |
| `reminders/edit_dialog.py` | `hint_line` 从一行字改成「本周 + 七格 + 数据至」 |
| `tests/test_app.py` | 改一条既有断言、加一条新断言 |
| `tests/test_holidays.py` | 加 `week_of()` 的纯逻辑用例 |

`hint_line` 在**每次建编辑框时重算** —— 联网更新会改数据，不能缓存。

## 5. 已知取舍

- **淡字对比度低于 3:1**（`#C6B99B` 对纸约 1.8:1）。这是有意的：那几格的作用是
  "占位，表明这天不弹"，不是给人读的内容。要看"今天周几"，深色格子和黄描边已经够了。
- **不做悬停提示**（用户最初的想法是悬停）。直接显示不用"发现悬停"，扫一眼就在那儿。
- 格子**不显示日期**（如 `09-25`）—— 一行放不下，且"本周"这个前缀已经把语义交代清楚。

## 6. 测试

`tests/test_app.py`：

- **改**：Task 5 那条 `any("法定节假日" in t for t in seen["labels"])` —— 那句话没了。
  改为断言七格齐全、且「本周」在标签里。
- **加**：七格的深浅必须与 `holidays.is_workday()` **逐日一致**（用当天现算对照，
  **不写死哪几天** —— 否则换一周跑就挂），且今天那格 `highlightthickness > 0`。

`tests/test_holidays.py`：`week_of()` 的纯逻辑（周一开头、跨月跨年、长度恒为 7）。

`tests/test_model.py` 不受影响。

## 7. 风险

- **布局宽度**：实测这行需要 378px，编辑框可用 424px，余量 46px。若以后改字号或加
  内容，先量 `hint.winfo_reqwidth()` 再改。
- **主题类控件**：新增的七格是 `tk.Label`，不是可交互控件 —— 测试那套"按控件类型找"
  的写法不受影响，但**按文本找 Label 的既有断言会受影响**（§6 已列出要改的那条）。
